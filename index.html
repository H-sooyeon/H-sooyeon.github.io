01 기록 작성 중 세션 만료로 데이터를 잃는 문제 해결
문제
  • "잇다"의 핵심 가치는 기록을 끊김 없이 작성하는 것이었으나, "작성 중 세션 만료로 처음부터 다시 써야 한다"는 사용자 피드백 발생
  • 기존 Access Token은 클라이언트 메모리에만 보관되어, 미들웨어·서버 컴포넌트·요청 어디서도 만료 감지 및 갱신 트리거가 불가능했음
해결
  • Next-auth(v5) 도입으로 세션을 암호화 쿠키 기반으로 재설계해 서버·클라이언트 어디서든 동일 세션 접근 및 갱신 가능하도록 수정 PR #138
  • 서버 컴포넌트 병렬 요청 시 RTR(Refresh Token Rotation) 재사용 에러 발생 → JWT 콜백 기반 갱신 로직 일원화 및 백엔드 Grace Period 도입 제안·적용 PR #145
  • Refresh Token 만료 7일 전 자동 갱신되는 Sliding Session 적용 Discussion #272
결과
  • 기록 작성 중 세션 만료로 인한 데이터 유실 문제 해결
  • 로그인 유지 경험 개선

02 환경별로 흩어진 인증 처리를 공통 fetch로 통합
문제
  • 인증 구조 개선 과정에서 서버·클라이언트·API 라우트마다 인증 헤더 주입 및 토큰 만료 처리 로직이 중복 구현되어 있음을 발견
  • 인증 처리 방식 변경 시 여러 곳을 일일이 수정해야 했고, 누락 시 인증 오류로 이어질 위험 존재
해결
  • 서버/클라이언트 환경별 Base URL을 자동 분기하는 공통 fetchApi 유틸 설계 — 인증 헤더 자동 주입, 401 시 토큰 갱신 후 재요청, 갱신 실패 시 로그아웃까지 일원화
  • TypeScript로 요청·응답 타입을 정의해 호출부가 인증 처리를 신경 쓰지 않도록 인터페이스 분리
  • AbortController 기반 타임아웃을 적용해 응답 지연 시 요청을 자동 중단하고 TIMEOUT으로 즉시 처리
결과
  • 인증 처리 로직 일원화로 코드 응집도 및 개발 생산성 향상
  • 인증 로직 변경 시 누락으로 인한 보안 리스크 감소
03 이미지 접근 보안 강화 및 캐시 구조 재설계
문제
  • "잇다"는 사용자의 일상을 기록하는 서비스로, 기록에 첨부되는 이미지는 대부분 개인적인 순간을 담고 있어 타인이 쉽게 접근할 수 있다면 프라이버시 문제로 이어질 수 있음
  • 백엔드 리소스 제약으로 이미지를 Presigned URL로 서빙 → URL만 있으면 인증 없이 접근 가능해 권한 우회 위험 존재, 요청마다 URL이 새로 발급되어 캐싱도 되지 않아 캐시 히트율이 0%에 가까움
해결
  • /api/media-image/[id] 형태의 불변 ID 기반 API Proxy 설계 — 매 요청마다 인증을 검증한 뒤 백엔드에서 Presigned URL을 받아 대신 서빙 PR #264
  • ETag(=media ID) + no-cache 적용 — 요청마다 인증을 재검증하면서도, 변경되지 않은 리소스는 304로 응답해 재다운로드·재인코딩 비용 절감
  • Route Handler에서 Sharp로 WebP 변환까지 함께 처리해 전송 용량도 최적화
결과
  • 인증 우회 위험을 제거하면서도 캐싱 가능한 구조 확보 (보안·성능 동시 달성)
  • 캐시가 전혀 동작하지 않던 이미지 응답을, 재조회 시 304로 응답해 캐시 히트가 발생하는 구조로 전환

01 채팅방 새로고침 시 프로필 유실 및 재입장 불가
문제
  • 채팅방 내에서 새로고침 시 유저 프로필이 초기화되고 소켓 연결이 끊겨 재입장 처리가 되지 않음
해결
  • 채팅방/유저 정보를 세션 스토리지에 저장하고, 새로고침 감지 시 자동 재입장 API 호출 PR #174
  • 중복 입장 방지 로직 추가 및 세션 초기화 중 대기 UI 표시
결과
  • 새로고침 후 이전 채팅방에 자동 재입장되고 프로필이 유지됨
02 다크모드 새로고침 시 라이트모드로 깜빡이는 현상 (FOUC)
문제
  • 다크모드 사용 중 새로고침하면 JS가 전역 상태를 초기화하기 전까지 라이트모드로 잠깐 깜빡이는 FOUC(Flash of Unstyled Content) 현상 발생
해결
  • 테마 설정을 전역 상태 대신 쿠키로 관리하는 서버 액션 구현, Next.js 서버에서 쿠키를 읽어 렌더링 이전에 테마 적용 PR #176
  • 아이콘 테마를 전역 상태 의존에서 CSS 기반으로 전환하여 JS 초기화 시점과 무관하게 올바른 테마 적용
결과
  • 새로고침 시 다크모드 깜빡임 현상 제거
03 가상스크롤 적용 후 채팅 메시지 튕김 현상
문제
  • 메시지가 누적될수록 모든 항목을 DOM에 렌더링해 스크롤 성능이 저하됨
  • 성능 개선을 위해 @tanstack/react-virtual을 도입했으나, 라이브러리가 top-to-bottom 기준으로 아이템 위치를 계산하는 구조여서 최신 메시지를 하단에 고정하려면 새 메시지 수신 시마다 scrollTop을 최하단으로 강제 이동해야 했음
  • 이 과정에서 virtualizer가 위치를 재계산하는 타이밍과 scrollTop 이동이 충돌해, 스크롤 중이거나 메시지를 전송할 때 화면이 위아래로 튕기는 현상 발생
해결
  • 스크롤 컨테이너에 scaleY(-1) CSS를 적용해 리스트 전체를 상하 반전, scrollTop=0이 항상 최신 메시지 위치가 되도록 구조 변경 (PR #141)
  • 각 메시지 아이템에도 scaleY(-1) 을 적용해 텍스트가 거꾸로 보이는 현상 방지, 새 메시지 추가 시 DOM 하단에 append되어 scrollTop이 변하지 않으므로 튕김 제거
  • 단, 컨테이너가 반전된 상태에서는 마우스 휠 스크롤 방향도 반전되는 문제 발생 → wheel 이벤트를 직접 가로채 scrollTop -= deltaY 로 방향을 보정
결과
  • 메시지 수와 무관하게 일정한 DOM 노드 수를 유지해 스크롤 성능 개선
  • 새 메시지 수신 및 전송 시 scrollTop 강제 이동이 없어져 화면 튕김 현상 제거
